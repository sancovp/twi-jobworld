# TWI Jobworld — the corrected base (THE PATTERN)

This repo is the **corrected Jobworld base**: one program that COMPILES a specialized AI company from
a single config file. It is the base of a fork-and-constrain producer tower (base → B6 → meta → Avi);
every tier is a fork of this that adds constraint. Canonical design lives in the monorepo at
`sanctuary-revolution-alpha/application/jobworld/` (`DESIGN.md`, `roadmap_states.md`,
`GROUND_TRUTH_2026-07-21.md`).

## The pattern (the heart)
**ONE config file drives everything.** `config.json` (see `config.example.json`) is COMPILED by
`server/render.py` into the Claude-Code component layout an instance runs on:

```
config.json + .secrets/mcp_state.json  ──server/render.py──▶  CLAUDE.md · agents/CEO.md ·
    .claude/agents/* · .claude/rules/* · skills/run-dept-*/SKILL.md · .mcp.json
```

Config **COMPILES** the system (code-generation); it does not parametrize a frozen machine. There is
no baked set of departments — the departments/agents/CEO-prompt/MCP-wiring are generated from the
config. **Tools = MCPs wrapped in skills** (Instantly, Apollo): a `run-dept-*` skill explains the
process and the MCP tools; agents follow directed skills, never raw tools ad-hoc.

## Layout
- `config.example.json` — the ONE config shape (business + departments + agents + MCP choice + runtime).
- `.secrets/mcp_state.example.json` — MCP credentials template. Live keys go in `.secrets/mcp_state.json`
  (gitignored) and are injected ONLY into `.mcp.json` env — never into any prompt/CLAUDE.md/rule.
- `server/render.py` — THE render step (config → instance layout). Stdlib-only; also the standalone CLI.
- `server/jobworld_agent.py` + `jobworld_server.py` — the CAVE engine + `/api/*` surface + dashboard.
- `agents/CEO.md` — the **bootstrap** CEO (compiles new instances). Each compiled instance gets its OWN
  CEO persona, generated by render.
- `skills/` — the pattern skills: `instantiate-jobworld` (compile an instance), `generate-employee`,
  `compile-claude-code-component` (prompt-plane build guide), `ceo-bootstrap`, + the `understand-*` set.
- `test/` — the real dry-run test: `jwtest.py` (produces typed test signals), `expected.py` (asserts
  them, authored independently — **producer ≠ asserter**), `test_ceo_dry_run.py` (renders a fixture,
  the CEO drives every step, asserts the trace). A test that can FAIL.

## Runtimes (config.runtime)
- `tmux-anthropic` — interactive `claude` in tmux on Anthropic (`jobworld_agent`). Default.
- `sdk-minimax` — headless `claude_agent_sdk` on MiniMax-M3 with OAuth fallback (`p_main_agent`).
Both consume the SAME compiled layout; only the CEO launcher differs.

## Laws (this repo)
- Config compiles; never hardcode departments in a script (that was the drift `instantiate.sh` fixed).
- Secrets live only in `.secrets/`; never in a prompt. A blocker is reported with its missing input,
  never fabricated. Every dir has a `CLAUDE.md`.
